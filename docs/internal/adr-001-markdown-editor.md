# ADR-001. Markdown-редактор: markdown как хранимый формат, правка визивигом

Статус: принят 2026-10-31 (имя пакета согласовано). Владелец решений — автор.

## Контекст

В коллекции есть просмотр markdown (`UidMarkdown` в ките: GFM-таблицы,
выноски, подсветка кода, оглавление, живые блоки через `blockRenderers`) и
визивиг `@dskripchenko/wysiwyg` 0.5 (свой contenteditable-движок, тулбар,
slash-меню, markdown-сокращения, таблицы, превью блоков ```mermaid / ```flow
и других). Визивиг хранит **HTML**; в markdown он умеет только выгружать
(`htmlToMarkdown`), и с потерями: без вложенных списков, таблиц,
`mark/sup/sub`.

Нужен редактор, у которого **значение — markdown** (репозиторий, вики,
README, поле формы), а правят его как в визивиге — по канонам нашего
визивига: тот же тулбар, slash-меню, сокращения, превью живых блоков.

Решение автора (2026-10-30): отдельный пакет в коллекцию, не для плагина
Confluence.

## Решения

1. **Пакет `@dskripchenko/markdown-editor`.** Vue 3, поверх
   `@dskripchenko/wysiwyg` (движок, тулбар, slash, история) и кита
   (`UidMarkdown` для превью, разбор markdown). Без сторонних зависимостей,
   ui / vue / wysiwyg — peer-зависимости.
2. **Компонент `MarkdownEditor`**, `v-model` — строка markdown. Режимы:
   - **визуальный** (по умолчанию) — визивиг;
   - **исходник** — текст markdown с подсветкой и номерами строк;
   - **рядом** — исходник и живой просмотр бок о бок.
   Переключение не теряет курсор там, где это возможно (позиция блока).
3. **Круговой обход markdown → HTML → markdown.** Это главное в пакете.
   - Markdown → HTML редактора: разбор кита (`renderMarkdown` с режимом
     «для редактора»: без якорей заголовков, живые блоки — карточками
     превью визивига, как ```mermaid сейчас).
   - HTML → markdown: `htmlToMarkdown` визивига **дописывается в самом
     визивиге** (источник), а не обходится в новом пакете: вложенные
     списки, списки задач `- [ ]`, GFM-таблицы с выравниванием, выноски
     `> [!NOTE]`, `mark`/`sup`/`sub` (как HTML), сноски, живые блоки как
     исходные fenced-блоки байт в байт.
   - **Нормализация, а не каша:** первый проход приводит документ к
     каноничному виду (маркер списков `-`, `**` для жирного, отступ 2/4 по
     настройке); каждый следующий проход ничего не меняет. Это закрепляется
     тестами на корпусе реальных документов (README пакетов коллекции,
     вики, документация) — идемпотентность и сохранность содержимого.
   - Неподдержанная конструкция (HTML-блок, сложная таблица) не ломается:
     становится нередактируемым блоком с исходником и правится в режиме
     исходника.
4. **Каноны визивига** — без своих UI-примитивов: тулбар, slash-меню,
   сокращения (`#`, `-`, `1.`, `>`, ```` ``` ````, `---`), вставка ссылок и
   картинок, таблицы, превью живых блоков с `blockRenderers` (одна
   регистрация работает и в просмотре, и в редакторе).
5. **Вставка.** Markdown из буфера вставляется как разметка, HTML (из Word,
   Google Docs, браузера) — через санитайзер визивига и сразу
   нормализуется в markdown.
6. **API**: `MarkdownEditor` (компонент), `toMarkdown(html)`,
   `fromMarkdown(md)`, событие `change`, `focus()`, `insert(md)`, локали
   ru/en через кит.

## Этапы

1. Визивиг: дописать `htmlToMarkdown` (п. 3) — патч/минор
   `@dskripchenko/wysiwyg`, тесты на круговой обход.
2. Кит: режим `renderMarkdown` для редактора, если текущего вывода не
   хватает — минор ui.
3. Пакет `markdown-editor`: компонент, режимы, вставка, корпус-тесты,
   браузерная проверка (реальный contenteditable — урок 0.2.0 визивига:
   jsdom-тестов мало).
4. Документация ×4, витрина в demo, публикация через changesets.

## Ответы автора (2026-10-31)

1. Имя `@dskripchenko/markdown-editor` — да.
2–3. Режим «рядом» и место показа в коллекции — по умолчанию: режим есть,
   показ — витрина пакета (страница с примерами) и demo-стенд после
   релиза.
