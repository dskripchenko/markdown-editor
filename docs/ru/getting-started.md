# Начало работы

```bash
npm i @dskripchenko/markdown-editor @dskripchenko/wysiwyg @dskripchenko/ui vue
```

```vue
<script setup>
import { ref } from 'vue'
import { MarkdownEditor } from '@dskripchenko/markdown-editor'
import '@dskripchenko/ui/styles/all.css'
import '@dskripchenko/wysiwyg/style.css'
import '@dskripchenko/markdown-editor/style.css'

const text = ref('# Заметки к релизу\n\nВерсия **3.1**.')
const mode = ref('visual')
</script>

<template>
  <MarkdownEditor v-model="text" v-model:mode="mode" min-height="320px" />
</template>
```

## Режимы

| Режим | |
|---|---|
| `visual` | Визивиг-редактор: тулбар, slash-меню (`/`), markdown-сокращения (`#`, `-`, `1.`, `>`, ```` ``` ````), таблицы, живые блоки. |
| `source` | Сам Markdown в моноширинном поле (Tab делает отступ). |
| `split` | Markdown и живой просмотр рядом (на узком экране — друг под другом). |

Переключатель показывает режимы из `modes`; при одном режиме его нет.

## Свойства

| Свойство | | |
|---|---|---|
| `v-model` | `string` | Markdown. |
| `v-model:mode` | `'visual' \| 'source' \| 'split'` | Режим; по умолчанию `visual`. |
| `modes` | `string[]` | Доступные режимы; по умолчанию все три. |
| `modeSwitch` | `boolean` | Кнопки режимов над редактором; `false`, когда режимы переключает сама программа (`v-model:mode`). По умолчанию `true`. |
| `toolbarTarget` | `string \| HTMLElement` | Где показывать тулбар визуального режима вместо места над текстом: собственная панель программы (элемент или CSS-селектор). |
| `toolbar` | `boolean` | Тулбар визуального режима над текстом; `false`, когда форматирование — из плавающего тулбара или у программы. По умолчанию `true`. |
| `bubble` | `boolean \| string[]` | Небольшой тёмный тулбар над выделением в визуальном режиме: `true` — жирный, курсив, подчёркнутый, зачёркнутый, код, ссылка, заголовок 2 и маркированный список; или свои кнопки. Нужен `@dskripchenko/wysiwyg` 0.15. |
| `frameless` | `boolean` | Без рамки: визуальный редактор, кнопки режимов, исходник и предпросмотр без рамок и фона — видна страница вокруг. Для визуального редактора нужен `@dskripchenko/wysiwyg` 0.15. |
| `placeholder` | `string` | Подсказка в пустом документе. |
| `readonly` | `boolean` | Только чтение во всех режимах. |
| `min-height`, `max-height` | `string` | Высота области правки. |
| `block-renderers` | `object` | Живые блоки: `{ mermaid: renderer }` — контракт `UidMarkdown` из кита; одни и те же в редакторе и просмотре. |
| `toolbar-items`, `slash-commands` | | Передаются визивиг-редактору. |
| `locale` | `'en' \| 'ru'` | Язык; по умолчанию — локаль кита. |
| `labels` | `object` | Отдельные строки поверх языка. |
| `image-base` | `string` | Папка (адрес с `/` на конце), от которой считаются относительные картинки: `img/a.png` показывается оттуда и сохраняется обратно как `img/a.png`, `../a.png` тоже. |
| `link-base` | `string` | База относительных ссылок в превью. |
| `linkSuggest` | `(query) => items` | Что предлагает `[[` по мере набора (внутренние ссылки): `{ label, insert, detail? }[]` или промис с ними; выбор пишет `[[insert]]`. Не задано — списка нет. |
| `saveImage` | `(file) => path` | Картинки, вставленные, перетащенные или выбранные кнопкой картинки на панели: хост сохраняет `File` и возвращает путь для Markdown (или промис с ним; `null` — пропустить); в позицию курсора пишется `![имя](путь)`. Не задано — картинки не принимаются. |

Формулы TeX (`$…$`, `$$…$$`) и `==выделение==` в визуальном режиме показываются нарисованными (с `@dskripchenko/ui` 1.26 и `@dskripchenko/wysiwyg` 0.10 и новее): формула — единый кусок, двойной щелчок правит её TeX, пункт **Формула** в slash-меню вставляет новую, а Markdown сохраняет её как написано; в исходнике её TeX подсвечивается.

YAML front matter в начале документа (его свойства) хранится ровно как написан; `#теги` в визуальном режиме показываются тегами (с `@dskripchenko/ui` 1.27 и `@dskripchenko/wysiwyg` 0.11).

События: `update:modelValue` и `change` с Markdown — только когда документ
правят, а не при загрузке. `update:mode`.

Наружу: `focus()`, `insert(markdown)` (в позицию курсора; в визуальном режиме —
уже форматированным), `value`.

## Правка на месте

Чтобы править страницу там, где она стоит, — текст выглядит как страница,
форматирование из панели над выделением:

```vue
<MarkdownEditor v-model="text" frameless bubble :toolbar="false" :mode-switch="false" />
```

Вид панели настраивается переменными редактора `--dsk-wysiwyg-bubble-*`.

## Круговой обход

Markdown отрисовывается в HTML редактора и пишется обратно из него. Первый
проход приводит документ к каноничному виду — `-` для маркированных списков,
`**` и `*` для выделения, заголовки через `#`, нумерация пунктов заново, — а
каждый следующий оставляет его как есть. Текст экранируется только там, где
символ иначе означал бы разметку: `1.5`, `a-b`, `(нетто)` остаются как
написаны.

Списки задач `- [ ]` / `- [x]` правятся как списки с флажками: щелчок по флажку
отмечает пункт, `[ ] ` или `[x] ` в начале пункта делает его задачей, Enter после
задачи начинает неотмеченную (`@dskripchenko/wysiwyg` 0.13 и новее; со старым они
сохраняются как написано).

То, чего визуальный редактор не умеет, сохраняется **как написано**:

- заголовки `####`, `#####`, `######`;
- выноски `> [!NOTE]`, `> [!WARNING]`…;
- HTML-блоки (`<details>`, `<div>`…);
- сноски `[^1]` и их определения;
- ссылки по ссылке `[текст][id]` и их определения.

В визуальном режиме такой блок показывает свой Markdown (с полосой слева);
правится он в режиме Markdown и сохраняется байт в байт.

## Без компонента

```ts
import { fromMarkdown, toMarkdown, normalize } from '@dskripchenko/markdown-editor'

fromMarkdown('# Привет\n\n- a')   // HTML редактора
toMarkdown('<h1>Привет</h1>')      // '# Привет\n'
normalize('* a\n* b')              // '- a\n- b\n' — один проход, как при сохранении
```

`toMarkdown` нужен DOM (браузер или jsdom). Обе функции принимают `{ imageBase }`:
относительные картинки разворачиваются для показа и обратно в относительные пути
при выводе.
